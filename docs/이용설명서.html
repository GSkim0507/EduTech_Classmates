1. 시스템 한눈에 보기

The Annoying Friend는 학생이 주장하는 글을 쓰는 동안 옆에서 깐깐하게 반응하는 AI 친구를 제공한다. 친구는 학생이 못 쓰면 잘난 척하고, 잘 쓰면 약 올라한다. 학생은 단순히 평가받는 게 아니라 친구를 약 올리기 위해 글을 다듬는다.

학습 모델

  • 4단계 글쓰기 — 서론 → 본론 → 결론 → 제목
  • '주장글쓰기 헌법' 기반 평가 — 매 페이즈마다 5~8개의 헌법 신호(thesis_present, argument_method_identifiable 등)를 LLM이 점수화하여 다음 응답의 톤·영역을 결정
  • 자유 채팅 없음 — 학생 입력은 글 textarea 하나뿐. 학생이 능동적으로 누르는 버튼(같이 고민 / 친구 설득 / 친구한테 보여주기 / 다음으로)이 모든 인터랙션

핵심 산출물

  • 학생: 완성된 한 편의 주장 글 + 친구의 마지막 평가(closure)
  • 교사/연구자: 모든 keystroke 단위가 아닌 의미 있는 액션 단위의 작성 여정 기록

2. 시작하기 (학생 입장)

  1. 로비 페이지 /에 접속한다.
  2. 이름(닉네임 가능), 학년(4·5·6), 글 주제를 입력한다.
  3. (선택) Claude API 키를 직접 입력 — 비워두면 운영자가 설정한 키 사용
  4. 시작하기 버튼을 누르면 /write/[sessionId]로 이동
참고 학생 입력 API 키는 브라우저 sessionStorage(annoying-classmate:api-key)에만 저장되며, DB에는 절대 들어가지 않는다. 탭을 닫으면 자동 소실.

3. 4단계 작성 흐름

📝 서론 intro
→
📑 본론 body × 3~5
→
🏁 결론 conclusion
→
🏷️ 제목 title
→
🎉 완료 done

각 단계마다 학생은 ① 글을 쓰고 ② 필요하면 같이 고민해줘로 도움을 받고 ③ 친구한테 보여주기로 평가를 받고 ④ 다음으로를 눌러 단계를 확정한다.

현재 단계 표시

상단 탭은 클릭 가능. 이전 단계를 확정했더라도 누르면 보기만 또는 다시 쓰기(회귀)를 선택할 수 있다. 미진입 단계는 비활성.

4. 핵심 4버튼 사용법

학생이 누를 수 있는 버튼은 페이즈마다 4종류로 통일된다.

🤝 같이 고민해줘

도움 요청 (학생 능동)

막힐 때 친구에게 도움을 청한다. 평가가 아니라 도움이다.

제한 각 문단·페이즈마다 2회까지
학생이 선택 💡 아이디어 / ✏️ 글의 짜임 / 🤷 전부 다 봐줘

🎯 친구한테 보여주기 / 친구 설득하기

평가 요청 (시스템 자동 평가)

5개 평가요소 + 헌법 신호로 LLM이 자동 평가하고 다음 톤(annoying/less-annoying)을 결정한다.

제한 무제한
본론에서 문단별로 따로 평가 가능

👀 본론 문단별 보여주기

본론 i문단 평가

본론은 문단마다 따로 평가받을 수 있다. 내부적으로는 submit 트리거와 같지만 paragraphIdx가 함께 전달된다.

API /api/sessions/[id]/turn (trigger=submit, paragraphIdx)

➡️ 다음으로 (commit)

현재 단계 확정 + 다음 단계 진입

서론·결론·제목은 1회 commit, 본론은 전체 한 번에 commit.

제약 본론은 최소 1문단 작성 시 가능. 정석은 3문단.

중요 이 4개 버튼을 누른 순간에만 학생의 글이 DB와 JSON 기록에 영구 저장된다. 키 입력만으로는 절대 DB에 들어가지 않는다 — 자세한 내용은 §8. 데이터 저장 정책 참고.

5. 친구 페르소나 & 승부 게이지

친구는 두 가지 모드를 오간다. 학생이 잘 쓸수록 친구가 약 올라하고(annoying), 못 쓰면 잘난 척한다(less-annoying). 이 reframing 덕에 학생은 "잘 쓰면 친구가 약 오르는" 게임을 즐기게 된다.

less-annoying (잘난 척)
"에이~ 그것도 모르겠어? 천천히 같이 해보자."
annoying (약오름)
"헐... 좋네. 근데 이건 어때? 인정 못 해 아직."

승부 게이지

친구 표정 아래 좁은 게이지가 있다. 학생이 잘 쓸수록 좌측이 길어지고 우측(친구 영역)이 빨갛게 변한다.

학생 72 : 친구 28

미평가 상태(서론 시작 시점)는 50:50. 평가가 발생할 때마다 재계산되며 시간순 변화는 따로 표시하지 않고 현재 값만 보여준다.

6. 본론 동적 다문단 (3~5)

본론 단계 진입 시 기본 3개의 textarea가 세로로 표시된다. 학생은 문단 수를 동적으로 조절할 수 있다.

  • + 문단 추가 마지막 textarea 아래 — 최대 5문단까지
  • − 문단 삭제 각 textarea 우측 상단 — 최소 3문단 유지
  • 문단별 평가 각 문단마다 도움/보여주기 버튼이 있어 따로 평가 가능
  • 일괄 commit 본론은 페이즈 전체를 한 번에 다음 단계로 보낸다 (paragraphIdx 0..N-1 모두 committed)
패널티 규칙 학생이 본론을 1~2문단만 작성하고 결론으로 넘어가면 bodyCommittedCount가 calibrator에 전달되어 친구의 다음 평가에 "본론이 너무 짧다"는 신호로 반영된다.

7. 돌아가서 다시 쓰기 (회귀)

이미 확정한 단계를 다시 고쳐쓸 수 있다. 상단 페이즈 인디케이터를 클릭하면 모달이 뜬다.

  • 그냥 보기만 — read-only로 펼쳐 확인
  • 다시 쓰기 — confirm 후 commit 해제, textarea로 재진입

회귀 시 draft_revisions에는 source='regress_uncommit' 마커 행이 추가되어 timeline에 흔적이 남는다. 분석 단계에서 학생의 메타인지 활동을 추적할 수 있다.

data/schema.sql 발췌
-- source 값:
--   student_write     : 처음 작성
--   student_revise    : 친구 피드백 후 수정
--   committed         : 확정
--   regress_uncommit  : 회귀해서 확정 해제

8. 데이터 저장 정책 (중요)

학생의 글은 3개의 서로 다른 매체에 분산 저장되며, 매체마다 보존 기간과 트리거가 다르다.

① 임시본

sessionStorage

학생이 키를 입력하는 동안 1.1초 debounce로 브라우저 메모리에 임시 저장. 탭 닫으면 자동 삭제. DB에는 절대 안 들어감.

② 정식 기록

Turso DB (libsql)

학생이 4개 액션 버튼을 누른 순간 1회만 INSERT. 모든 분석·관리자 UI의 source of truth.

③ JSON 저널

data/sessions/[id].json

DB와 동일한 이벤트를 사람이 읽을 수 있는 JSON으로 미러. 백업·외부 분석용. .gitignore 처리됨.

저장 트리거 매트릭스

이벤트sessionStorageDBJSON
학생이 글자 입력 (keystroke)✅ 1.1s debounce❌❌
🤝 같이 고민해줘 클릭🗑️ 항목 삭제✅ draft + turn × 2✅ draft_saved + turn_student/assistant
🎯 친구 설득하기 / 보여주기 클릭🗑️ 항목 삭제✅ draft + turn × 2 + calibration✅ 4종 이벤트
➡️ 다음으로 클릭🗑️ 항목 삭제✅ committed draft + commit row✅ commit
마지막 페이즈 commit (=done)🗑️ 세션 전체 일괄 삭제✅ closure✅
학생이 탭을 닫음🗑️ 브라우저 자동——

코드 발췌

app/write/[sessionId]/page.tsx
// keystroke 1.1초 debounce → sessionStorage 만 기록 (DB POST 없음)
function scheduleAutosave(text, targetPhase, targetParagraphIdx) {
  saveTimerRef.current = setTimeout(() => {
    sessionStorage.setItem(
      draftStorageKey(sessionId, tphase, tidx),
      JSON.stringify({ content: text, source, savedAt: Date.now() })
    );
  }, 1100);
}

// 액션 버튼이 눌리는 시점에만 1회 DB POST
async function flushAutosave(...) {
  await fetch(`/api/sessions/${sessionId}/draft`, { method: 'POST', ... });
  sessionStorage.removeItem(draftStorageKey(sessionId, tphase, tidx));
}
lib/sessionJournal.ts
export async function appendJournalEvent(sessionId, event) {
  const existing = (await readJournal(sessionId)) ?? {
    sessionId, createdAt: new Date().toISOString(), events: [],
  };
  existing.events.push(event);
  await writeJournal(existing);  // atomic: write to .tmp, then rename
}

9. 관리자 페이지

  1. /admin/login에서 .env.local의 ADMIN_PASSWORD 입력
  2. /admin 메인 — 전체 세션 리스트 (학생명·주제·진행 페이즈·마지막 갱신)
  3. /admin/sessions/[id] — 세션 상세
    • Timeline 탭 — draft revisions + turns를 시간순으로 표시. 연속된 두 draft 사이는 inline diff (jsdiff 기반 char-level)로 변화 표시.
    • CSV export — /api/admin/export-csv로 분석용 데이터 일괄 다운로드
인증 정책 (현재) proxy.ts 미들웨어가 /admin/* 경로만 보호한다. 학생 영역은 아직 인증이 없다 — Phase 2(docs/future-improvements.md A 그룹)에서 학생 회원 시스템과 함께 도입 예정.

10.5 JSON 저널 위치와 관리

  • 경로: data/sessions/[sessionId].json
  • git ignore 등록됨 (.gitignore의 /data/sessions/)
  • 각 파일은 단일 세션의 모든 액션 이벤트를 timestamp 오름차순으로 보관
  • 분석 스크립트 예시는 후속 작업: scripts/analyze-journal.mjs (계획)

10.6 주요 API 엔드포인트

경로메서드역할
/api/sessionsPOST새 세션 생성
/api/sessions/[id]GET세션 전체 상태(drafts·turns·calibrations) 조회
/api/sessions/[id]/draftPOST액션 직전 draft 1회 INSERT (flushAutosave)
/api/sessions/[id]/turnPOST같이 고민 / 친구 설득 trigger
/api/sessions/[id]/commitPOST현재 단계 확정 + 다음 단계 진입
/api/sessions/[id]/uncommitPOST회귀 (commit 해제)
/api/sessions/[id]/closurePOST세션 종료 평가 (마지막 페이즈 commit 시 자동 호출)
/api/sessions/[id]/exportGET한 세션의 모든 데이터 JSON 다운로드

10.7 트러블슈팅

  • "Session not found" — TURSO_DATABASE_URL이 잘못됐거나 DB 초기화가 안 됐다. npm run db:init 재실행.
  • Claude API 403 — ANTHROPIC_API_KEY 만료. 학생이 직접 입력한 키가 우선 사용되므로 로비 화면에서 키 입력 가능.
  • 한글이 깨짐 — Google Fonts(Gowun Dodum / Jua) 로드 실패. app/layout.tsx의 <link>가 막힌 네트워크인지 확인.
  • JSON 저널 파일이 안 생긴다 — data/sessions/ 디렉토리 쓰기 권한 확인. 헬퍼가 mkdir -p로 자동 생성하지만 권한이 막히면 console.warn으로 남고 DB 작업은 계속 진행된다.
