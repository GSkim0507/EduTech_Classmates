# 추후 개선 사항 (Phase 2 이월)

본 문서는 2026-05-09 사용자 QA/QC 결과 도출된 요청사항 중 **현 ICCE 5/12 마감 범위에서 제외**된 항목을 별도로 보존한다. ICCE 시뮬레이션 walkthrough 이후 정식 연구·학교 현장 배포 단계에서 본격 적용한다.

## A. 회원/인증 시스템

### A-1. 회원 관리 (요청 7.1)
- 회원가입 → 로그인 → 이용 프로세스 도입
- 학생 데이터(글쓰기 기록·학업성취도 추적) 영구 회원 단위로 누적
- 현재 sessionId 기반 익명 시스템 → 회원 단위로 전환

### A-2. 빈틈없는 인증 (요청 7.2)
- 모든 학생 페이지(`/`, `/write/[id]`, `/result/[id]`, `/api/sessions/*`) 인증 필수
- 비로그인 상태에서 sub-페이지 직접 접근 시 모두 로그인 페이지 redirect
- 현재 proxy.ts는 `/admin/*`만 보호. 학생 영역까지 확장 필요.

### A-3. 슈퍼 어드민 + 일반 어드민 (요청 7.3)
- 현재: `.env.local`의 `ADMIN_PASSWORD` 단일 값으로만 인증
- 변경: 슈퍼 어드민 계정 (`admin@star.edu` / `admin1234`) DB 보관
- 슈퍼 어드민이 일반 어드민 계정 발급/회수 가능
- 권한 모델: super > admin > teacher (선택) > student
- DB에 `users`, `roles`, `user_roles` 테이블 추가 필요

### A 작업 시 주요 고려사항
- 비밀번호 해싱 (bcrypt 또는 Argon2)
- 세션 토큰 (JWT 또는 server-side session, Turso 호환)
- 학생 본인은 자기 데이터만, 교사·관리자는 담당 학생 데이터만, 슈퍼 어드민은 전체
- 학생 동의·보호자 동의 UI (IRB 단계에서)
- 비밀번호 재설정 (이메일 기반)

## E. 산출 — 최종 분석 보고서

### E-1. 교사·학부모용 글쓰기 보고서 (요청 5.3)
- 학생 1편 글쓰기 세션 종료 후 자동 생성되는 인쇄 가능한 보고서
- 포함 내용:
  - 학생 정보 + 주제 + 작성 일시
  - 최종 글 (서론/본론/결론) 확정본
  - 글쓰기 여정 요약 (몇 번 수정, 몇 번 도움 요청, 몇 번 보여주기)
  - 5개 평가요소(주장 명확성·근거 적절성·근거 관련성·표현 적절성·짜임 완성도) 점수 추이 차트
  - AI 친구의 closure (full/partial/impasse) + 핵심 코멘트
  - **교사/학부모 친화적 자연어 요약** (LLM 생성, 학습 강점·약점·다음 글쓰기 제안)
  - PDF 다운로드 / 인쇄 버튼

### E-2. 보고서 디자인 원칙
- 학생용 친근 톤이 아니라 차분한 공식 톤 (제3자가 봐도 신뢰)
- A4 1–2장 분량으로 압축
- 차트 1–2개 (Recharts 또는 단순 SVG)
- 그래프·수치보다 **자연어 해설**이 중심

### E-3. 학교 현장 누적 보고서 (선택)
- 학생 1명의 여러 세션을 합친 학기·학년 단위 변화 추적
- 회원 시스템(A) 도입 후에야 가능

## 작업 우선순위 (참고)

1. **A-1 회원가입·로그인 인프라** (DB users 테이블 + 비밀번호 해싱 + 세션)
